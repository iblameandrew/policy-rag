# PolicyRAG

A small, boring RAG service over a dummy employee handbook. A user sends `{query, role}`. A local privacy gate may refuse the request. If it does not, Chroma retrieves only chunks that role is allowed to see. A mocked LLM (or OpenAI if `OPENAI_API_KEY` is set) answers **only** from those chunks and cites them.

This is not "chat with a PDF." Retrieval is the security boundary. The language model is not an authorization oracle. Embeddings run locally (`all-MiniLM-L6-v2`). Handbook text is not sent to a third party unless you opt in with an API key.

The dummy PDF is titled **[TEST] EMPLOYEE HANDBOOK & POLICY MANUAL (DUMMY)** / Acme Dynamics. It is not real people, not real payroll, and not real SSNs. Ingest reads `data/employee_handbook.pdf` (generated by `scripts/generate_handbook.py`). A separately provided Global Tech filler PDF may sit at the repo root; it is not the index source.

## Why SSN is blocked before RAG

Questions about Social Security Numbers are a **privacy** problem, not a ranking problem. If we embedded the query, searched Chroma, and then asked a model to "please not reveal the SSN," we would still have (1) put SSN intent into the index query, (2) pulled payroll chunks into context, and (3) trusted a generator to keep a secret. The assignment twist is Lock A: a local regex + keyword gate. On hit we return a fixed refusal (`route=privacy_gate`). We do not embed, we do not query Chroma, we do not call the LLM. Logs record `blocked=ssn_intent` with SSN digits scrubbed.

## Why salary is blocked by metadata, not by the LLM

"What is user X's salary?" does **not** look like an SSN question, so Lock A lets it through. Named salaries live in a **restricted** payroll appendix. That appendix is labeled at ingest (`classification=restricted`, `allowed_roles=hr,admin`). Lock B is a Chroma `where` pre-filter built from `app/acl.py`. Employee queries never see restricted rows. Admin/HR queries may. The LLM never receives "this user is admin, you may reveal salaries." If the filter returned nothing, the model is told it has no sources and must say it does not know.

## Why an airlock alone is not enough

A prompt airlock (Lock A) stops SSN **intent**. It does not stop a well-formed salary question. If restricted chunks are still retrieved, they sit in the context window and any generator — mocked or real — can restated them. The metadata pre-filter is the actual ACL. Fetch-then-filter in Python is not enough: with `k=4`, the four nearest neighbours can all be payroll rows, the post-filter drops them, and you either return empty or silently replace them with whatever came back unfiltered. Pre-filter so the ANN search itself cannot return restricted ids to an employee.

`role` is a **stand-in for a JWT claim**. Production would take the role from a verified token, never from the prompt text, and never from an untrusted JSON field the client can edit. Unknown roles fail closed to `public`.

## Two locks

| Lock | What it stops | When it runs |
|------|----------------|--------------|
| A. `app/privacy.py` | SSN digits + SSN intent | Before retrieve, before LLM |
| B. Chroma `where` on `classification` | Payroll appendix / restricted | Inside `Chroma.query`, not after |

## How to run (local)

Python 3.11+. From the repo root:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Unix:    source .venv/bin/activate
pip install -r requirements.txt
python -m scripts.generate_handbook
python -m scripts.ingest --pdf data/employee_handbook.pdf
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

First MiniLM download happens at ingest if `POLICYRAG_FAKE_EMBEDDINGS` is unset. After that the model cache is local.

## How to run (Docker)

```bash
cp .env.example .env    # gitignored; do not commit it
docker compose up --build
```

On first start, if the `chroma` volume is empty, the API ingests `data/employee_handbook.pdf` (generating it if missing). `/health` is served on `http://localhost:8000/health`.

The image installs CPU torch, then `sentence-transformers`, and pre-downloads `all-MiniLM-L6-v2` at build time so runtime can stay offline.

## How to run tests

Tests use `POLICYRAG_FAKE_EMBEDDINGS=1` (see `tests/conftest.py`) and a temp Chroma dir. No network and no API key.

```bash
pytest
# or inside the image:
docker compose run --rm -e POLICYRAG_FAKE_EMBEDDINGS=1 api pytest -q
```

Ten live questions against `POST /ask` (PTO, salary employee vs admin, SSN gate). Server must be up, or use `--in-process`:

```bash
python -m scripts.test_endpoint
python -m scripts.test_endpoint --in-process
```

## Example curls

PTO, employee (should answer from the handbook with citations):

```bash
curl -s http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d "{\"query\":\"What is the PTO policy?\",\"role\":\"employee\"}"
```

Salary, employee (no payroll appendix chunks; model may only use compensation philosophy or say it does not know named pay):

```bash
curl -s http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d "{\"query\":\"What is user X's salary?\",\"role\":\"employee\"}"
```

Salary, admin (may retrieve the restricted payroll appendix; SSNs in the index are `[SSN_REDACTED]`, salary figures may remain):

```bash
curl -s http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d "{\"query\":\"What is user X's salary?\",\"role\":\"admin\"}"
```

SSN, anyone (403 JSON, `route=privacy_gate`, no retrieve, no LLM):

```bash
curl -s http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d "{\"query\":\"what is Jane's SSN?\",\"role\":\"admin\"}"
```

## API shape

`POST /ask` `{query, role}` where `role ∈ {public, employee, hr, admin}`.

Success (`route=rag`): `{answer, citations[], blocked:false, block_reason:null, route, role, latency_ms}`.

Blocked SSN (`HTTP 403`, `route=privacy_gate`): fixed refusal, empty citations, `block_reason=ssn_intent`.

Also: `GET /health`, `POST /ingest`.
